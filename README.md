# Talento — HR-платформа для Telegram-ботов вакансий

SaaS-платформа: компания за 10 минут поднимает собственного Telegram-бота для публикации
вакансий и приёма откликов. HR управляет всем через веб-панель, кандидат — только через бота.

```
Кандидат (Telegram)
      │
Telegram Bot API ──webhook──▶ POST /webhook/{bot_id}/{secret}
                                   │
                              FastAPI  ──▶  PostgreSQL 16
                              │   │              Redis (FSM, кэш, rate limit)
                              │   └──▶  Celery ──▶ уведомления HR, статусы кандидату
                              │
HR (браузер) ──▶ React SPA ──▶ REST /api/v1/...
```

**Один процесс обслуживает всех ботов.** Webhook определяет тенанта по `bot_id` в URL,
проверяет секрет (в пути + в заголовке `X-Telegram-Bot-Api-Secret-Token`), отвечает `200`
мгновенно и обрабатывает апдейт в фоне.

## Структура бота

Главное меню — две колонки, разделы, которых у компании нет, просто не показываются
(а не выводятся пустыми), и оставшиеся кнопки перестраиваются, чтобы не оставлять дыр:

```
[🏢 О компании]        [📍 Филиалы]        ← «Филиалы» только при режиме филиалов
[📋 Вакансии]          [📰 Новости]
[☎️ Контакты / Адрес]  [📨 Мои заявки]
[🌐 Язык]                                  ← только если языков больше одного
```

**Вакансии.** Выбор «🔥 Актуальные / 🌐 По филиалам» показывается только тогда, когда за
обеими половинами что-то есть. Нет актуальных — сразу список филиалов; выключен режим
филиалов — сразу плоский список. Меню с одной живой кнопкой и одной мёртвой хуже, чем его
отсутствие.

- 🔥 **Актуальные** — плоский список вакансий с флагом «Актуальная», без привязки к филиалу.
  Одна вакансия может быть и актуальной, и в филиале — тогда она видна в обоих местах.
- 🌐 **По филиалам** — филиал → его вакансии.

Кнопка «⬅️ Назад» на карточке вакансии возвращает в тот список, откуда пришли: действие
несёт в себе scope (`vac:{id}:{scope}`), иначе актуальная вакансия отправляла бы кандидата
в филиал, который он не выбирал.

**Филиалы** — отдельный раздел-справочник: все активные филиалы (не только те, где есть
вакансии), фото, адрес и точка на карте, если заполнены обе координаты.

**Новости** — постранично по 5. Это осознанно: рассылка неограниченной ленты по сообщению
на запись — самый быстрый способ упереться во флуд-лимиты Telegram.

**Анкета остаётся динамической** — вопросы берутся из конструктора вакансии, как и раньше.
Никакой выгрузки в Google Sheets нет: заявки живут в БД и в панели.

## Кнопки бота

Все кнопки — **нижняя клавиатура** (reply keyboard), а не inline-кнопки под сообщением.
Клавиатура остаётся на экране, пока кандидат не перейдёт на другой экран.

Технически это другой транспорт: inline-кнопка приносит `callback_data`, а нажатие нижней
кнопки приходит обычным текстовым сообщением. Поэтому каждая отправленная клавиатура
записывает в Redis карту `{подпись: действие}` (`app/bot/menu.py`), и входящий текст
разбирается через неё. Все действия сходятся в один `_dispatch_action`, так что у каждой
кнопки ровно одна реализация.

Что из этого следует:

- **Карта заменяется, а не дополняется.** Нижняя клавиатура не исчезает после отправки
  сообщения, поэтому кандидат может пролистать вверх и нажать кнопку с прошлого экрана.
  Активной считается только текущая клавиатура — старые подписи никуда не ведут.
- **Подписи главного меню работают всегда**, даже если Redis очистили: это фиксированные
  строки из `texts.py`, они распознаются без карты. Бот переживает рестарт.
- **Дубли подписей разводятся.** Две вакансии могут называться одинаково; к повтору
  добавляется невидимый символ, чтобы обе кнопки остались различимыми ключами.
- **Мультивыбор перерисовывается.** Нижнюю клавиатуру нельзя отредактировать на месте, как
  inline, поэтому каждое переключение галочки отправляет клавиатуру заново. Это цена
  формата: чуть больше сообщений в переписке.
- На каждом шаге анкеты есть «✖️ Отменить», а в списках — «🏠 Главное меню», чтобы из
  любого экрана был выход одним нажатием.

Inline-обработчик оставлен как совместимость: у кандидатов, начавших диалог до этого
изменения, старые кнопки продолжают работать через тот же диспетчер.

## Тип вопроса «Дата / время»

Восьмой тип в конструкторе анкеты. Кандидат отвечает обычным текстом — специальной
клавиатуры нет, только «Пропустить»/«Отменить», как у короткого текста, — но ответ
проверяется строго по одному из трёх форматов, который HR выбирает при создании вопроса:

| Маска | Пример | Формат |
|---|---|---|
| `date` (по умолчанию) | `08.02.1999` | ММ.ДД.ГГГГ |
| `datetime` | `08.02.1999 10:08` | ММ.ДД.ГГГГ чч:мм |
| `time` | `10:08` | чч:мм |

Хранится маска в `questions.validation` (том же JSONB-поле, что уже использовалось для
min/max числовых вопросов) — новая колонка не понадобилась, миграция только расширяет
CHECK на `type`.

**Проверка двухступенчатая: сначала форма, потом календарь.** Regex ловит `8.2.1999`
(нет нулей) прежде, чем `datetime.strptime` дойдёт до проверки, что 30 февраля не
существует — раздельно, потому что это разные ошибки кандидата и должны ловиться
одинаково чисто, а не полагаться на то, что `strptime` сам отбросит `8.2.1999` (не
отбросит — примет как 8 февраля).

Под вопросом бот показывает подсказку формата и пример: `Формат: MM.DD.YYYY
(например: 08.02.1999)`. Без неё маска была бы не видна кандидату вообще — он не мог бы
угадать, что `2/8/99` не подходит, а `08.02.1999` подходит. Сам токен формата
(`MM.DD.YYYY`) не переводится ни в одном языке — это техническое обозначение, как
плейсхолдер в date-picker'е, а не предложение; переводится только текст вокруг него.

## Форматирование текста вопроса

Текст вопроса в конструкторе анкеты редактируется **WYSIWYG** — поле всегда показывает
жирный как жирный, ссылку как ссылку, а не `**звёздочки**`. Отдельного режима «Просмотр»
нет: то, что HR видит во время печати, и есть то, что получит кандидат. Выделил слово,
нажал «Жирный» на панели инструментов (Ж / К / Ч / З / код / ссылка) — слово визуально
стало жирным на месте, курсор остаётся там же, можно сразу печатать дальше. Повторное
нажатие на то же самое выделение снимает форматирование (проверено и на вложенности:
`<b><i>слово</i></b>` → выделить весь `<b>` целиком → «Жирный» ещё раз → остаётся только
`<i>слово</i>`, без разбитых тегов).

Технически поле — `contenteditable`-div, а не `<textarea>`: панель инструментов работает
через Selection/Range API (сознательно не `execCommand`, у которого разные браузеры
генерируют несовместимую разметку), Enter вставляет один `<br>` (не новый `<div>` — иначе
текст на следующей загрузке визуально сдвинулся бы), вставка из буфера обмена всегда идёт
как обычный текст (сторонний HTML не нужно ни санитайзить, ни сверять с собственным набором
тегов). При каждом изменении дерево сериализуется обратно в Markdown
(`src/lib/markdown.ts::htmlToMarkdown`) — именно эта строка, а не DOM, уходит в
`onChange`/API/БД. Ссылка редактируется во всплывающем поле (Popover) с URL: клик по
ссылке-Ж — открывается с уже подставленным адресом и кнопкой «Убрать ссылку».

Authoring-формат — обычный Markdown, но **отправляется кандидату всегда как Telegram HTML**,
не MarkdownV2. Причина: MarkdownV2 требует экранировать `_*[]()~\`>#+-=|{}.!` — буквально
везде, и обычная фраза вроде «Зарплата 3.000.000 сум!» превращается в невалидное сообщение,
которое Telegram отклонит с 400, а кандидат просто не получит вопрос. HTML-режим требует
экранировать только `&`, `<`, `>` — это делает бот сам, автору вообще не нужно об этом
думать.

Конвертация устроена так, что **сломать её текстом невозможно**: экранирование идёт первым
проходом (значит implant вроде `<script>` никогда не долетит как реальный тег), парные
маркеры (`**bold**`, `_italic_`, `__underline__`, `~~strike~~`, `` `code` ``,
`[текст](ссылка)`) превращаются в теги, а всё, что не распознано как маркер — включая
непарную звёздочку или `snake_case_name` — остаётся как есть, без ошибок и без проверочного
шага. Ссылки на `javascript:`/`data:`-схемы преобразуются в обычный текст без href.

В заявке (`applications.answers[].question_text`) хранится **сырой Markdown, как его
написал HR** — не HTML и не отрендеренный текст, — так что панель и CSV-экспорт показывают
вопрос ровно в том виде, в котором его редактировали.

## Загрузка картинок

Логотип компании, фото филиала, картинка вакансии и новости загружаются прямо из панели —
клик или drag-and-drop, превью, крестик для удаления. Файл уходит на
`POST /api/v1/uploads/image` сразу, а форма продолжает хранить обычный `photo_url`. Так
медленная загрузка не блокирует набор текста, а неудачная — не теряет остальной черновик.

**Формат определяется по содержимому файла, а не по заголовку и не по расширению** — и то
и другое подконтрольно клиенту. Принимаются JPEG, PNG, WebP и GIF по сигнатуре первых
байтов; всё остальное отклоняется с 422.

SVG в списке нет намеренно: это XML, внутри которого может лежать `<script>`, и отдача его
с нашего же домена была бы хранимым XSS. Файл `logo.png` с SVG внутри и заголовком
`image/png` не пройдёт — проверяются байты.

Остальные ограничения: 5 МБ на файл, путь вида `images/{company_id}/…` (чтобы политика
бакета могла рассуждать о владельце), имя файла санитайзится, расширение берётся из
распознанного формата, а не из того, что прислал браузер.

## Мультиязычность

Компания включает нужные языки в «Настройки → Компания → Языки бота» и заполняет контент
на каждом из них: у форм вакансии, филиала, вопроса и текстов бота появляются вкладки
языков. Кандидат выбирает язык при первом `/start` (или меняет через `/lang`), и видит
вакансии, анкету и кнопки на своём языке.

**Как это устроено.** У каждой переводимой таблицы есть обычные колонки (`title`,
`description`, …) — это **базовое значение** — и колонка `translations JSONB` вида
`{"uz": {"title": "Barista"}}`. Чтение идёт как `translations[lang][field]` с откатом на
колонку. Отсюда три полезных следствия:

- миграции данных не нужно — существующие строки уже валидны;
- `ORDER BY title`, фильтры и экспорт CSV продолжают работать по настоящей колонке;
- **переводить можно частично**: непереведённое поле показывается на базовом языке, а не
  исчезает. В панели вкладка языка помечена точкой — зелёная значит «что-то заполнено».

Несколько правил, которые стоит знать:

- Базовый язык нельзя выключить — на него откатывается всё непереведённое (API вернёт 422).
- Варианты ответов переводятся **по одному полю на вариант**, а не свободным текстом: длина
  списка обязана совпадать с базовой, иначе индекс ответа уехал бы на другой вариант.
  API отклоняет несовпадение, а форма физически не даёт его создать.
- В заявку всегда пишется **базовая** формулировка вопроса и ответа, даже если кандидат
  отвечал по-узбекски. HR, фильтры и CSV видят один словарь. Кандидату при подтверждении
  анкеты его ответы показываются на его языке.
- Уведомление о смене статуса приходит кандидату на том языке, на котором он откликался.

Язык кандидата определяется по первому совпадению: выбор в боте (Redis, 90 дней) →
`candidates.language` → `language_code` его Telegram-клиента → язык компании по умолчанию.
Из них учитываются только языки, которые компания реально публикует.

**Добавить четвёртый язык** (например казахский): добавьте словарь строк в
`backend/app/bot/texts.py` и код в `SUPPORTED_LANGUAGES` в `backend/app/core/i18n.py`.
Больше ничего менять не нужно — панель и бот подхватят его автоматически.

## Быстрый старт

```bash
cp .env.example .env
```

Сгенерируйте два секрета и впишите их в `.env`:

```bash
python3 -c "import secrets,base64,os; print('JWT_SECRET=' + secrets.token_urlsafe(48)); print('BOT_TOKEN_ENCRYPTION_KEY=' + base64.urlsafe_b64encode(os.urandom(32)).decode())"
```

```bash
docker compose up --build
```

- Панель — http://localhost:5173
- API + Swagger — http://localhost:8000/docs
- Миграции применяются автоматически сервисом `migrate` до старта `api` и `worker`.

### Вариант B — локально, без Docker

## Подключение настоящего бота

Telegram доставляет webhook **только на публичный HTTPS**. Для локальной разработки нужен
туннель:

```bash
ngrok http 8000
```

Впишите выданный адрес в `.env` и перезапустите API:

```
BASE_URL=https://<ваш-id>.ngrok-free.app
```

Дальше: @BotFather → `/newbot` → скопировать токен → панель → «Настройки → Бот» (или мастер
онбординга). Платформа сама вызовет `getMe` и `setWebhook`.

Проверить, что Telegram доволен: «Настройки → Бот» показывает состояние webhook, включая
последнюю ошибку доставки.

### Служебный бот для уведомлений HR (опционально)

Отдельный бот, через которого HR получают сообщения о новых заявках:

```
PLATFORM_BOT_TOKEN=...
PLATFORM_BOT_USERNAME=talento_notify_bot
```

Его webhook: `{BASE_URL}/webhook/platform/{secret}`, где `secret` — первые 32 символа
sha256 от `PLATFORM_BOT_TOKEN + JWT_SECRET`. Получить готовый URL:

```bash
cd backend && .venv/bin/python -c "from app.api.webhook import platform_webhook_secret; from app.core.config import settings; print(f'{settings.BASE_URL}/webhook/platform/{platform_webhook_secret()}')"
```

Затем в панели: «Настройки → Уведомления» → «Получить код» → отправить `/link КОД` боту.
Без `PLATFORM_BOT_TOKEN` раздел уведомлений просто скрыт, остальное работает.

## Тесты

```bash
cd backend && .venv/bin/pytest -q
```

212 тестов на реальных PostgreSQL и Redis (схема использует JSONB и нативные UUID —
на SQLite это была бы проверка другой системы). Нужна база `talento_test`:

```bash
createdb talento_test
```

Что покрыто:

- **Изоляция тенантов** — параметризованный тест бьёт каждый скоупнутый эндпоинт чужим
  `X-Company-Id`; отдельные тесты на чтение/запись чужих вакансий и заявок по прямому id.
- **Безопасность webhook** — неверный секрет в пути, отсутствующий и неверный заголовок,
  неизвестный бот, отключённый бот.
- **Шифрование токена** — токен не возвращается наружу и не лежит в БД в открытом виде.
- **Полный проход анкеты в боте** через настоящий aiogram Dispatcher: сеть подменена
  фейковой сессией, но хендлеры, FSM, валидация и запись в БД работают по-настоящему.
- **Тип «Дата/время»** — все три маски принимают валидный ввод и отклоняют невалидный
  (отсутствие нулей, несуществующие даты вроде 30 февраля, час 25 или 24), API отклоняет
  неизвестную маску и на create, и на patch, полный проход анкеты в боте для каждой маски,
  необязательный вопрос можно пропустить.
- **Форматирование вопроса** — конвертация Markdown → Telegram HTML (все маркеры, ссылки
  с скобками в URL, непарные маркеры, `snake_case` не путается с курсивом), защита от
  HTML-инъекции и `javascript:`/`data:`-ссылок, полный проход анкеты в боте с реально
  отформatированным вопросом.
- **Загрузка картинок** — SVG и HTML под видом PNG отклоняются, заголовок Content-Type
  игнорируется в пользу байтов, расширение берётся из содержимого, путь с `..` в имени
  обезвреживается, лимит размера, изоляция по компаниям.
- **Навигация** — шесть разделов меню, скрытие «Филиалов» без режима филиалов и
  перестроение сетки, справочник филиалов с точкой на карте, 🔥/🌐 развилка и её
  схлопывание, возврат из актуальной вакансии в актуальный список, постраничные новости.
- **Нижние клавиатуры** — отдельный набор, который водит бота как живой кандидат: только
  нажатия, никаких callback-ов. Проверяется в том числе, что ни один экран не отдаёт
  inline-клавиатуру, что кнопка с прошлого экрана не срабатывает, что подписи меню
  переживают очистку Redis и что одинаковые названия вакансий остаются различимыми.
- CRUD, reorder, удаление филиала с переносом вакансий, duplicate копирует вопросы,
  история статусов, экспорт CSV.
- **Мультиязычность** — откат по полям, отказ от несовпадающих по длине списков вариантов,
  запрет на отключение базового языка, выбор языка в боте, и главное: кандидат отвечает
  по-узбекски, а в заявке лежит русская формулировка.

## Решения, которые стоит знать

**Один Dispatcher на процесс, экземпляр `Bot` на апдейт.** Dispatcher хранит регистрацию
хендлеров — она одинакова для всех тенантов и дорого пересоздаётся, поэтому строится один
раз. `Bot` — это, по сути, сам секрет: токен плюс HTTP-сессия. Кэшировать его по тенантам
значило бы держать в памяти процесса токены всех клиентов бессрочно и течь сессиями при
ротации токена. Поэтому он создаётся на один апдейт и сразу закрывается.

**Снапшот анкеты в Redis.** При старте анкеты замораживаются не только `question_ids`, но и
сами вопросы (текст, тип, варианты, валидация). Фиксации одних id мало: если HR удалит
вопрос, пока кандидат его заполняет, форма сломается. Снапшот содержимого гарантирует, что
кандидат допройдёт ту анкету, которую начал.

**404 вместо 403 на чужие записи.** `403` подтвердил бы, что id существует, и позволил бы
перебором выяснить состав чужого тенанта.

**Переводы в JSONB, а не в отдельной таблице.** Переводы всегда читаются вместе с
родительской строкой и никогда не запрашиваются отдельно, так что join ничего не давал бы,
зато стоил бы N+1 на каждом списке вакансий в боте. JSONB оставляет запись атомарной.

**Экспорт CSV — синхронный,** а не через Celery: это один индексированный запрос, а HR ждёт
файл в том же клике. Тело функции легко переносится в задачу, если объёмы вырастут.

**Токены в localStorage.** Компромисс в пользу удобства для внутренней панели. Переход на
HttpOnly-cookie — изменение бэкенда, не UI.

## Прод

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

`DOMAIN` и `ACME_EMAIL` в `.env` — Caddy сам выпустит и продлит сертификат, что закрывает
требование Telegram к HTTPS для webhook.

CI (GitHub Actions): линт, миграции, тесты бэкенда на живых PostgreSQL/Redis; type-check и
сборка фронтенда.

### Чек-лист безопасности

| Что | Где |
|---|---|
| Изоляция тенантов | `app/core/deps.py` — `get_current_company` + `get_owned_or_404`; каждый роутер фильтрует по `company_id` |
| Шифрование токенов ботов | `app/core/crypto.py` — AES-256-GCM, ключ из env |
| Секрет webhook | `app/api/webhook.py` — `secrets.compare_digest` по пути **и** заголовку |
| Rate limiting | webhook — 30 rps на бота (Redis); slowapi подключён для auth |
| Хеширование паролей | bcrypt, `app/core/security.py` |
| Перечисление email | login отдаёт одинаковую ошибку на «нет юзера» и «неверный пароль» |
| Удаление ПДн кандидата | `DELETE /api/v1/applications/{id}` |
| Заголовки безопасности | `Caddyfile` — HSTS, nosniff, DENY, referrer-policy |
| Загрузка файлов | `app/api/uploads.py` — формат по сигнатуре байтов, SVG запрещён, лимит 5 МБ, путь скоуплен по компании |

**Ротация `BOT_TOKEN_ENCRYPTION_KEY` делает все сохранённые токены нерасшифровываемыми** —
считайте ключ постоянным для окружения.
